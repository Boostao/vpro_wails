# PC-ORD Break Report

## Source and availability

Normal `Sb12OnAction` / `sb12btn02` opens `USysBreakReport` in report preview.
Its window caption is **VPro Break Report**, its visible heading is
**PC-ORD Break Report**, and its visible columns are **PC-ORD Break Code**
(left, bound to `BreakCode`) and **VPro Reference** (right, bound to `Reference`).
The query projects those columns in the opposite order:

```sql
SELECT DISTINCT USysBreakTable.Reference, USysBreakTable.BreakCode
FROM USysBreakTable;
```

This is the global preserved VPro64 table, without current project, Site Unit
or hierarchy filtering. `Order` and `PlotNumber` do not participate in DISTINCT.
There is no source ORDER BY, report grouping, linked child report or active
Open/Load/Format/Print event binding. The footer uses `Now()` and
`"Page " & [Page] & " of " & [Pages]`; query calibration does not qualify that
native timestamp, pagination, page geometry or physical printing.

The source table has nullable LONG `Order`, nullable TEXT255 `Reference` and
`BreakCode`, nullable TEXT8 `PlotNumber`, and a nonunique `BreakCode` index.
Fixture zero-length text exercises query behavior, not original write authority.

returns detached literal nullable pairs and deduplicates byte-identical pairs.
Its technical NULL-first BreakCode/Reference ordering is an explicit desktop
adaptation, not source locale/report ordering. It reuses the shared calibrated
printable-ASCII key with Subzone Matrix while retaining operation-specific

Implementation, focused validation and independent review are separate steps.
