## Shared calculation and input boundary

The [workbook kernel](../lifeformworkbook.go) reuses the independently accepted
[Lifeform planner](LIFEFORM_SUMMARY_CONTRACT.md) and
[attribute planner](SPECIES_ATTRIBUTE_SUMMARY_CONTRACT.md). They deliberately
have different physical weighting:

- Lifeform uses source global insertions, SINGLE boundaries and later plot rejoin.
- Attribute counts use raw vegetation/SU/attribute join fanout and declared pivots.

The [combined reader](../lifeformworkbookread.go) captures Veg, SU, USysAllSpecs,
LifeformCodes and USysSppAttributes in one owned SQL/file snapshot. It does not
call two independent public previews and join potentially different observations.
The complete five typed physical tables remain detached approval evidence.
Unavailable attributes cannot produce a success-shaped Lifeform-only workbook.

The kernel checks common ownership, ordered memberships, literal typed units,
physical denominators, complete catalogue associations and six original attribute
definitions/category shapes. Existing Excel Unicode/XML/UTF-16 bounds and source
31-unit worksheet-name transformation remain authoritative. Collisions and
surrogate splits fail explicitly; no suffix, omitted unit or overwritten sheet.
NULL and empty unit identities remain distinct in mapped sheet/provenance data.
Formula-looking text is stored as literal text.

The very-hidden `_VPRO_Source` sheet preserves both complete typed previews and
the explicit detail vector as hex-chunked JSON. Ordered header insertion is
essential: map iteration can change shared-string indices and exact XLSX bytes,
invalidating an otherwise unchanged approval. Repeated byte-equality tests cover
identical preparations with/without details.

## Review and publication

[LifeformWorkbookService](../lifeformworkbookservice.go) is separately authorized
by literal `VPRO_LIFEFORM_WORKBOOK=true`; absent/false remains disabled. The
frontend gate is independently `VITE_LIFEFORM_WORKBOOK=true`. Neither gate enables
the existing Lifeform or species-attribute preview endpoints.

`GetReview(ctx, contextID, requestJSON)` requires exactly six explicit boolean
detail values in source order:
SRank/Wetland/WeedStatus/RedBlue/ASMR/Climate. Missing, NULL, non-boolean,
extra/missing array elements, malformed Unicode and duplicate/unknown members
are rejected before repair/defaulting.

`ExportReviewed(ctx, contextID, requestJSON)` additionally requires the exact
reviewed approval hash and a literal `.xlsx` destination. Approval binds raw
five-table evidence, owned paths/context, both reports, detail options, worksheet
mapping and exact workbook bytes. Fresh source revalidation occurs before the
irreversible publication and after it. Existing shared atomic no-replace staging,
byte verification and ownership guards are reused.

Known pre-publication failures retain an explicit no-file outcome and permit
reviewed retry. Published cleanup/cancellation failures preserve the path/hash and
`do not replay` receipt instead of discarding the committed bit. Publication is
not advertised as cancellable.
